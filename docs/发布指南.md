# MarkKnife 构建发布指南(小白版)

> 这份文档面向**没有任何发布经验**的人,从零讲清楚:怎么发一个新版本、用户怎么收到自动更新、出问题了怎么排查。
> 照着做即可,不需要理解每一个细节;想理解的话每节都有「原理」说明。

---

## 一、先搞懂几个概念(1 分钟)

| 名词 | 大白话解释 |
|---|---|
| **构建(build)** | 把源代码变成用户能双击安装的安装包(`.dmg` / `.msi` / `.exe`) |
| **发布(release)** | 把安装包放到网上,用户能下载的过程。我们发到 GitHub Release 页面 |
| **GitHub Actions(CI)** | GitHub 提供的「云端机器人」:你推一个 tag,它自动在云端的 Mac 和 Windows 电脑上帮你构建、发布,全程不用你动手 |
| **tag(标签)** | 给某次代码提交贴的版本标记,比如 `v0.1.0`。**推送 tag = 按下发版按钮** |
| **自动更新(updater)** | 用户打开 app 时,app 自己去检查有没有新版本,有就提示更新。不需要用户重新去网站下载 |
| **签名密钥** | 一对「私钥 + 公钥」。发布时用**私钥**给更新包盖章,用户的 app 用内置的**公钥**验章,防止更新包被坏人掉包 |

## 二、整体流程一张图

```
你本机                      GitHub 云端                          用户电脑
─────────                  ─────────────────────────            ─────────────
改版本号
git commit
git tag v0.2.0   ──推送──▶  GitHub Actions 自动开工:
git push origin v0.2.0      ├─ Mac 云电脑:打 Apple 芯片包
                            ├─ Mac 云电脑:打 Intel 芯片包
                            ├─ Windows 云电脑:打 msi/exe
                            ├─ 用私钥给更新包签名(.sig)
                            └─ 发布到 Release 页面
                                     │
                                     ▼
                            Release 里有:
                            安装包 + 更新包 + latest.json
                                     │
                       用户打开 app ─┘
                       app 读 latest.json → 发现新版 → 验签 → 提示更新 ✅
```

## 三、本项目已经配好的东西(了解即可,不用动)

这些是**一次性配置**,已经完成。换电脑/出事故时才需要看「第八节:灾难恢复」。

### 1. 发版工作流文件

[`.github/workflows/release.yml`](../.github/workflows/release.yml) —— GitHub Actions 的「剧本」,定义了:推 `v*` 开头的 tag 时,自动在 3 台云电脑上并行构建:

- macOS **Apple 芯片**(arm64)
- macOS **Intel 芯片**(x86_64)
- **Windows**(msi + exe 两种安装包)
- ~~Linux~~(暂时注释掉了,需要时取消 `release.yml` 里两处注释即可恢复)

全部构建成功后,自动把草稿 Release 转为**正式发布**。

### 2. 签名密钥(本机)

| 文件 | 作用 |
|---|---|
| `~/.tauri/markknife_updater.key` | **私钥**(盖章用,绝不能泄露、绝不能提交进代码仓库) |
| `~/.tauri/markknife_updater.key.pub` | **公钥**(验章用,已写进 `tauri.conf.json`,随 app 发给用户) |
| `~/.tauri/markknife_updater.password` | 私钥的**口令** |

> ⚠️ **重要**:请把私钥和口令的内容备份到你的密码管理器。这台电脑坏了/重装了,没有备份就只能换密钥(见第八节)。

### 3. GitHub 上的 Secrets(云端的保险柜)

位置:GitHub 仓库 → **Settings → Secrets and variables → Actions**

| Secret 名 | 内容 |
|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | 私钥文件的完整内容 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 私钥口令 |

CI 构建时从保险柜里取出私钥来签名。Secret 一旦保存,任何人(包括你)都**看不到内容**,只能覆盖更新。

### 4. 自动更新配置

在 [`src-tauri/tauri.conf.json`](../src-tauri/tauri.conf.json) 里:

- `"createUpdaterArtifacts": true` —— 构建时额外产出「更新包」(`.app.tar.gz` / 安装器)+ 签名文件(`.sig`)
- `plugins.updater.endpoints` —— 用户 app 检查更新的地址:
  `https://github.com/jaaksi/markknife/releases/latest/download/latest.json`
  (永远指向「最新一次 Release」里的版本清单,发新版后用户自动感知)
- `plugins.updater.pubkey` —— 内置公钥,验签用

## 四、日常发版:你只需要做这几步 ⭐

### 第 1 步:改版本号(3 个文件要一致)

| 文件 | 改哪里 |
|---|---|
| `src-tauri/tauri.conf.json` | `"version": "0.2.0"` |
| `src-tauri/Cargo.toml` | `version = "0.2.0"` |
| `package.json` | `"version": "0.2.0"` |

> 版本号规则:`主版本.次版本.修订号`。日常加功能 → 中间那位 +1;只修 bug → 最后一位 +1。
> **必须比上一版大**,否则用户的 app 不会认为有更新。

### 第 2 步:提交并推送

```bash
git add -A
git commit -m "chore: 发布 v0.2.0"
git push origin master
```

### 第 3 步:打 tag 并推送(= 按下发版按钮)

```bash
git tag v0.2.0
git push origin v0.2.0
```

> tag 必须以小写 `v` 开头(`v0.2.0`),这是 workflow 里约定的触发条件。

### 第 4 步:等 CI 跑完(约 5–15 分钟)

两种方式看进度:

- **网页**:打开 `https://github.com/jaaksi/markknife/actions`,点最上面那条正在跑的记录,能看到 3 个构建任务的实时日志。绿勾 ✓ = 成功,红叉 ✗ = 失败。
- **终端**(装了 GitHub CLI 的话):
  ```bash
  gh run watch --repo jaaksi/markknife   # 实时滚动显示,跑完自动退出
  ```

> 第一次构建慢(15–20 分钟,要从零编译所有依赖);之后有缓存,通常 5–10 分钟。
> 注意:缓存超过 7 天不用会被 GitHub 回收,久不发版后的第一次会再慢一回。

### 第 5 步:验证发布结果

1. 打开 `https://github.com/jaaksi/markknife/releases` —— 应能看到新版本,资产(Assets)里有:
   - `MarkKnife_x.y.z_aarch64.dmg`(Mac Apple 芯片)
   - `MarkKnife_x.y.z_x64.dmg`(Mac Intel)
   - `MarkKnife_x.y.z_x64_en-US.msi` 和 `MarkKnife_x.y.z_x64-setup.exe`(Windows)
   - 若干 `.tar.gz` / `.sig`(自动更新用,用户不用手动下载)
   - `latest.json`(版本清单)
2. 旧版本的 MarkKnife 打开后,应该会收到更新提示。

**到这里发版就完成了。** 🎉

## 五、用户视角:自动更新是怎么发生的

1. 用户打开 app,app 向 `releases/latest/download/latest.json` 发请求
2. `latest.json` 里写着最新版本号和各平台更新包地址
3. app 对比版本:线上 > 本地 → 弹「发现新版本」
4. 用户确认 → 下载更新包 → **用内置公钥验签**(防掉包)→ 安装 → 重启完成

> 由此可知:**`latest.json` 里的版本号必须大于用户手里的版本**,这就是第四节第 1 步要改版本号的原因。

## 六、CI 失败了怎么办

### 怎么看失败原因

网页:Actions → 点失败的那条 → 点红叉的任务 → 展开红叉的步骤,看最后几十行日志。

终端:
```bash
gh run list --workflow=release -L 3 --repo jaaksi/markknife   # 列最近几次
gh run view <run-id> --log-failed --repo jaaksi/markknife      # 只看失败日志
```

### 常见失败对照表

| 日志里的关键词 | 原因 | 解决 |
|---|---|---|
| `Wrong password for that key` | 私钥口令不对(secret 配错) | 重新核对两个 Secret 的内容;注意 tauri-cli 2.10 的「空口令」有 bug,**必须用非空口令** |
| `error[E0599]` / `cannot find ...`(Rust 编译错) | 代码只在 Mac 上测过,用了平台专属 API | 用 `#[cfg(target_os = "macos")]` 之类的条件编译隔离(参考 `lib.rs` 里 `RunEvent::Opened` 的处理) |
| `pnpm install` 失败 / lockfile 报错 | `pnpm-lock.yaml` 和 `package.json` 不同步 | 本地跑 `pnpm install` 后把 lockfile 一起提交 |
| 前端 `tsc` / `vite build` 报错 | 前端代码有错 | 本地先跑 `pnpm build` 修到通过再发版 |

### 修完之后怎么重发(同一个版本号)

tag 已经指向旧提交,需要「删掉重打」:

```bash
git push origin master                 # 先把修复推上去
git tag -d v0.2.0                      # 删本地 tag
git push origin :refs/tags/v0.2.0      # 删远端 tag
git tag v0.2.0                         # 在最新提交上重打
git push origin v0.2.0                 # 再次触发 CI
```

> 如果失败那次已经建出了草稿 Release,去 Releases 页把那个草稿删掉再重跑,避免资产混淆。

## 七、不用 CI,在本机手动构建(可选)

平时不需要;只是想本地打个包试试时用。

```bash
# 因为开了 createUpdaterArtifacts,本地构建也必须提供签名私钥:
TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/markknife_updater.key)" \
TAURI_SIGNING_PRIVATE_KEY_PASSWORD="$(cat ~/.tauri/markknife_updater.password)" \
pnpm tauri build
```

产物在 `src-tauri/target/release/bundle/` 下。

注意:
- Apple 芯片的 Mac 默认只能打出 **Apple 芯片包**;要打 Intel 包需先 `rustup target add x86_64-apple-darwin`,再加 `--target x86_64-apple-darwin`
- **Mac 上打不了 Windows 包**(跨系统不能交叉编译),Windows 包只能靠 CI
- 手动构建的包不会自动出现在 Release 里,只是本地文件

## 八、灾难恢复

### 换了新电脑 / 这台重装了

私钥和口令**只存在于** `~/.tauri/` 和 GitHub Secrets 里:

- 有密码管理器备份 → 把两个文件还原到新机器的 `~/.tauri/` 即可
- 没备份 → 私钥拿不回来了,但**不影响发版**(CI 用的是 GitHub Secrets 里的副本);只是本地手动构建用不了。真要彻底重置见下条

### 私钥泄露了 / 想换一把钥匙

```bash
# 1. 生成新钥(口令自定,务必非空并保存好)
./node_modules/.bin/tauri signer generate -w ~/.tauri/markknife_updater.key --password "你的新口令" --force
printf '%s' "你的新口令" > ~/.tauri/markknife_updater.password

# 2. 把新公钥(~/.tauri/markknife_updater.key.pub 的内容)替换进
#    src-tauri/tauri.conf.json 的 plugins.updater.pubkey,提交推送

# 3. 更新 GitHub Secrets
gh secret set TAURI_SIGNING_PRIVATE_KEY < ~/.tauri/markknife_updater.key -R jaaksi/markknife
printf '%s' "你的新口令" | gh secret set TAURI_SIGNING_PRIVATE_KEY_PASSWORD -R jaaksi/markknife
```

> ⚠️ 换钥匙的代价:**老版本 app 内置的还是旧公钥**,验不过新钥签的更新包,会收不到自动更新。已发布过版本后换钥匙,需要引导存量用户手动下载一次新版。所以钥匙能不换就不换。

### Secrets 忘了配 / 被删了

去仓库 Settings → Secrets and variables → Actions,按第三节的表格重新添加两个 Secret(内容取自本机 `~/.tauri/` 下的两个文件)。

## 九、已知注意事项

- **macOS 安装包是临时签名(ad-hoc)**,没有付费的 Apple 开发者证书。用户**第一次**打开会被 Gatekeeper 拦截,需要「右键 → 打开」或在系统设置里允许。要彻底消除需购买 Apple Developer(99 美元/年)并配置公证,届时再改 CI。
- **Windows 安装包未签名**,SmartScreen 可能提示「未知发布者」,点「仍要运行」即可。
- **Linux 构建已注释保留**在 `release.yml` 里(矩阵里的 `ubuntu-22.04` 项 + 「安装 Linux 构建依赖」步骤),需要时取消注释即可。
- GitHub 提示部分 Action 的 Node 20 将弃用(2026-09),不影响当前使用;届时升级 `actions/checkout` 等版本号即可。
